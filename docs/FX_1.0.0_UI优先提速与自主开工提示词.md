# FX 1.0.0 / FX Hook — UI 优先提速、整体功能归并与中断恢复执行补充档

**用途：** 配合 FX 两份长期交接档和《FX_1.0.0_UI优先自主推进与中断续接执行总指令.md》使用。新窗口直接读取并开工。  
**仓库：** `vip-svip/SY`  
**分支：** `fx-v1.0.0-unified-hook-integration`  
**版本：** 固定 FX 1.0.0；未经核对不得更改 `versionName=1.0.0` / `versionCode=10000`。  
**原则：** UI 页面推进优先、完整功能批次、并行处理、少量有效验证、GitHub 持久化、对话中断自动续接。

---

## 1. 用户纠正后的开发优先级

此前开发节奏存在明显问题：花费过多时间重复盘点、围绕边缘 Bug 反复修改、不断调整测试脚本和触发 Actions，导致主 UI 和 FX 业务域的整合页面推进不明显。新窗口必须改变工作分配。

### 默认顺序

1. **先推进 FX 原生 UI 与业务页面覆盖率。** 完成六个主 Tab 和 Ad/VPN/隐私/脚本/Hook 的统一导航与原生页面；来源 APK 只作为功能对照，不保留独立来源应用导航。
2. **再按页面批次接通后端。** 页面对应真实数据源、服务、Root API、系统权限、持久化和错误回读；不允许只做静态外观或假按钮。
3. **P0 安全问题例外并行处理。** 断网、VPN 槽位冲突、DNS 错路由、Hosts 写坏、数据丢失、权限越界、Root 命令注入、扫描误报安全、崩溃/ANR 等会造成损害的问题，发现后可立即优先修复，不必等待 UI 批次。
4. **功能进度优先于测试数量。** 以完成的页面组、原功能映射数、真实交互和后端闭环衡量进度；测试只用于防回归，不得让测试脚本/Actions 成为主要工作内容。

UI 优先不等于假实现：后端尚未接通的控件必须显示清楚的“尚未接入/暂不可用”状态，并禁止伪造运行中、保存成功或操作成功。先建立 UI 和明确的数据/业务接口契约，再集中接线。

## 2. 固定 UI 范围与推进顺序

### 2.1 FX 六个主 Tab（顺序不可变）

1. VPN
2. Ad
3. 隐私
4. 脚本
5. Hook
6. 设置

重点先解决：底部栏始终显示和高度正确；顶部错误横幅不能遮挡；Tab 切换、旋转、返回、进程重建后页面状态能恢复；VPN 开关与直连/全局/规则控件不乱位；设置始终第六；不得把其他 Tab 的主体业务挪进设置。

### 2.2 主 Tab 页面组

**VPN：** 总开关、直连/全局/规则、节点和订阅、连接状态、错误、DNS/代理状态、应用规则入口。保留用户已删除的限制：不加“快速配置”，不擅自增加“应用”区。UI 要覆盖连接中、成功、失败、第三方 VPN 占槽、Root Proxy 可用/不可用。真实状态未接通时不得显示已连接。

**Ad：** Tab 唯一显示名称为 Ad；Hosts 是 Ad 内部功能页，数据必须分开。本地系统 Hosts、远程订阅、允许/阻止规则、白名单、隐私过滤来源不能混成一个列表。Hosts 页面必须是实际文本文件编辑器：读取、搜索、分页/增量、编辑、保存、外部修改差异、备份/回滚。订阅页显示来源、数量、更新时间、错误和更新状态。

**隐私：** 按原分类展示面板、应用、规则、白名单、真实权限状态、开关、说明和保存状态。反诈、广告、水印、开屏、跟踪和隐私规则分开；FX 反诈规则仅限大陆反诈中心/96110 相关内容。

**脚本：** 脚本列表、搜索、导入/导出、编辑器、任务/定时、运行/停止、权限和日志。未实现运行能力必须明确不可用，不得伪造执行成功。

**Hook：** 首页状态、应用列表（图标/名称/包名）、搜索筛选、逐应用详情、会员选项、自定义 Hook、规则组、状态、错误、日志、导入/导出。Root、LSPosed/LSP、Accessibility 和 Android 权限必须读取系统实际状态。

**设置：** 仅保留外观与个性化（五种模式、壁纸、主题、动效）、权限入口、备份恢复、通知/诊断偏好、许可证和关于。严禁出现迁移应用、Dia/游龙/GKD 来源应用入口或业务设置。

### 2.3 来源功能到 FX 业务域的页面映射（不是独立应用导航）

所有来源能力必须拆分并归入 FX 自己的页面、路由和统一状态：
- **Ad**：广告总开关与多层过滤、DNS、Hosts、应用 Hook/Accessibility、共享数据面、规则/订阅、Firewall、Whitelist、Stats/Summary、Tile/Widget/Tasker/计划任务。
- **VPN**：代理节点/订阅、直连/全局/规则、分应用路由、DNS、防泄漏、MITM/HTTPS CA、MITM Script、连接日志与自动恢复。
- **隐私**：FX 隐私面板、游龙安全护盾、Root/模块/LSPosed 状态、扫描、风险详情、名单、救援与完整性。
- **Hook**：Dia Hook/Frida/DEX/监控/扩展、GKD 选择器与自动化、广告/开屏/更新/隐私检测 Hook、逐应用配置和自定义规则。
- **脚本**：Frida JS、MITM 网络脚本、浏览器 UserScript/扩展，以及 Surge/Quantumult X/Loon/Shadowrocket/Stash/Egern/Clash/Mihomo/sing-box 等生态的解析、API adapter 与真实 runtime。
- **设置**：仅全局视觉、系统授权入口、备份恢复、通知/诊断和关于；不放来源应用入口。

页面保留原功能/数据兼容，不保留原应用独立三级导航、独立主界面、外部 APK 启动或来源应用返回栈。旧来源 Activity 可作为内部实现暂存，但必须由 FX 业务页直接进入，标题/返回/Tab 高亮都显示 FX 的业务归属。

## 3. UI 页面批次的完整标准

一次选择 1–3 个紧密相关页面，不要同时散改十几个不相关文件。每个页面组应包含：

- 页面路由、标题、层级、返回/取消链正确；
- 原始主要控件、列表、表单、弹窗、菜单、编辑器和批量交互有对应位置；
- 加载中、空数据、错误、无权限、不可用、成功/失败状态都有明确 UI；
- 搜索、筛选、分页、滚动、软键盘和页面重建行为合理；
- 控件有明确的数据模型/配置键/API 契约；未接通后端时清楚显示未接入，不产生假结果；
- 视觉布局不能只靠源码 grep 宣称完成。没有设备或 UI 自动化环境时，诚实标记视觉/真机未验证。

完成 UI 页面组后，下一批按该页面接通真实后端：读取初始值 → 用户操作 → 调用真实 API/服务/Root → 读取回真实结果 → 更新 UI → 保存/恢复 → 处理权限拒绝和失败回滚。

## 4. 主动查漏与未完成任务矩阵

接手 AI 不得把下面清单机械地全量扫描一遍；每轮只快速恢复全局状态，再选择当前最高价值页面组核对原始 APK、Manifest、Smali、资源和现有实现。每个条目状态只能为：`未检查 / 缺失 / 部分实现 / 已实现未验证 / 已验证 / 有意不迁移（原因）`。

| 工作线 | 已知要继续核对/补齐的事项 | 不得误报的内容 |
|---|---|---|
| FX 主壳 | 六 Tab、顶部横幅、底栏高度、VPN 控件、页面恢复、设置第六 | 仅有 Tab 字段不等于 UI 已验收 |
| Dia UI | 原始 Activity/菜单/弹窗映射、Frida 脚本库/编辑器、Hook 页面、扩展和系统工具 | Frida 模板不等于完整 server/injector/gadget 生命周期 |
| 游龙广告 UI | DNS/订阅/规则详情/Firewall/Whitelist/Stats/Tile/Widget/Tasker/计划任务 | 页面存在不等于规则和实际流量已工作 |
| 安全护盾 UI | 扫描/风险详情/批量清理/名单/病毒库/Stellar 页面和内部导航 | 扫描不完整或数据不可用不得显示安全完成 |
| Hook UI | 首页、应用图标/搜索、逐应用配置、会员选项、自定义 Hook、日志/导入导出 | 配置文件写入不等于 LSPosed 已注入或授权成功 |
| Hosts | 真正编辑系统 hosts、外部修改回读、差异/分页/原子写入/回滚 | 订阅规则列表不等于 hosts 文件编辑器 |
| VPN/DNS | 共享 VpnService/TUN、直连/全局/规则、节点、DNS 上游、失败回退 | Android 同一用户/配置文件只有一个活动 VPN 槽；不许多个 VpnService 互抢 |
| 隐私 | 面板 UI、权限状态、白名单、规则分类、真实系统状态 | 本地偏好开关不等于系统级隐私功能生效 |
| 脚本 | 编辑器/任务 UI、QuickJS、API 桥、超时/取消/沙箱 | 识别脚本头部不等于兼容对应脚本平台 |
| 工程质量 | Manifest、权限、前台服务、进程生命周期、升级迁移、数据恢复、Root 安全 | 静态检查不等于构建/安装/真机验收 |

历史 Bug 必须继续覆盖：顶部横幅、底部 Tab、VPN 模式错位、订阅导入、返回丢状态、功能误放设置、隐私空壳、Hook 列表缺失、长列表/大文件卡顿、权限显示不一致、服务停止后 UI 假运行、病毒库空响应覆盖缓存、扫描不完整误报安全、Frida 目标/脚本状态恢复。

## 5. 加速规则：停止测试补丁循环

### 每批开发怎么分配时间

- 主要时间用于页面/功能实现；不要以测试数量代替开发进度。
- 一批次只围绕一个完整页面组，先把相关源码/资源/原始实现一次读取齐，再集中实现。
- 同一模块尽量一次成组提交；不要每个小问题单独改一行、提交一次、再重复触发 Actions。
- 同一页面最多先做一轮针对性验证；同模块多个页面完成后做一次模块回归；Gradle 全构建/全量 Actions 留到阶段节点。
- 若 CI 自动触发，不要为同一源码重复 push 来“再试一次”。读取失败 job 的具体日志并定位根因。
- 测试失败两次后必须改变排查方法；不准连续反复改断言、fixture 或 patcher 让红灯变绿。测试契约确实过时时，先证明原契约与现行为不一致，再同时改测试和产品实现。
- 不允许把大量时间花在不影响当前页面的低风险小 Bug。记录后排入下一批；但 P0 风险必须优先。

### 进度指标

有效进度按以下项目记录：

1. 原始页面/组件映射到 FX 的数量和未映射数；
2. 本批真实完成的页面组数；
3. 原控件/交互/返回链完成情况；
4. 已接通真实后端的控件/功能数；
5. 未完成的最高优先级页面/功能；
6. 验证等级和未验证项。

**不要使用**提交数量、测试数量、日志数量或新建文件数量作为主要进度指标。

### 并行方式

同时维护最多三条明确工作线：

- UI 主线：主 Tab、导航和页面完成；
- 来源能力归并线：Dia → Hook/Script，游龙广告 → Ad，安全护盾 → 隐私；
- P0/后端线：独立的网络、存储、安全关键问题。

独立文件可并行读取/编辑；`MainActivity.java`、Manifest、Gradle、统一状态/配置等共享文件必须协调后顺序整合。当前工具不支持真实多 Agent 时，只能声称并行工具调用/分线工作，不得虚称启动 Agent。

## 6. GitHub 提交与对话中断保护

唯一开发位置：`vip-svip/SY` / `fx-v1.0.0-unified-hook-integration`。

1. 修改前读取最新 HEAD、base tree、目标文件当前版本；旧聊天/旧 SHA 不能覆盖新状态。
2. 不强制推送；用 expected SHA/非强制更新。分支前进时重新读取并重放修改。
3. 每个有效页面/功能批次提交时，同步更新 `docs/FX_1.0.0_LIVE_CONTINUATION_STATE.md`，最好与代码在同一个 commit。
4. 每次对话可能中断：状态文件必须记录当前 HEAD、最近批次、变更路径、真实验证、失败路线、未完成项和下一批可直接开工的文件/页面。
5. 新窗口先读取最新 HEAD 和状态文件，跳过已验证完成项；只针对下一批页面读取相关文件，不能重做全量盘点。
6. 不生成编号备份，不创建无意义分支，不把临时目录当作项目唯一进度记录。
7. 三套应用和全体验收完成前，不打包/交付最终 APK 或 KernelSU ZIP。

## 8. 最终验收目标

- FX 1.0.0 单 APK、单入口、单生命周期；
- 固定六 Tab 和完整原生页面层级；
- Dia、游龙广告、游龙安全护盾的原始页面/组件/业务逐项映射；
- Hook 两套历史能力融合、真实权限状态和逐应用配置；
- VPN/DNS/Hosts 真实流量与文件路径可用；
- 隐私、脚本引擎和规则系统可真实工作；
- 升级、回滚、数据安全、权限和 Android 版本兼容有证据；
- 静态、单测、UI、构建、安装、真机验证分开记录。

“自动优化到完美”作为持续目标；不得无证据声称完美或已全部完成。
