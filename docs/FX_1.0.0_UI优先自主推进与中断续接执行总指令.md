**文档用途：** 新 ChatGPT 窗口、新 AI 或上下文中断后，直接恢复 FX 项目并继续实际开发。

**唯一开发分支：** `fx-v1.0.0-unified-hook-integration`  
**固定版本：** `FX 1.0.0`；目标 `versionName=1.0.0`、`versionCode=10000`（先核实，不得擅改）

## 0. 给接手 AI 的第一原则

用户明确纠正了此前开发节奏：**长期反复盘点、围绕边缘 Bug 打转、不断修改小补丁/触发整套 Actions，却没有明显推进 UI 和主功能。现在必须改变执行顺序。**

从本文件开始，默认优先级调整为：

1. **先推进前端 UI 与页面迁移完整度。** 先让主 Tab、迁移应用导航、各原应用的页面层级、主要列表/表单/弹窗/菜单/编辑器和状态区完整可见、可导航、可交互。
2. **随后按页面功能批次接通后端。** 每个 UI 页面对应明确的数据源、服务/脚本调用、权限、持久化和错误处理。不要只做静态外观，也不要用假数据、假状态或空按钮冒充完成。
3. **用完整功能批次开发。** 同一页面/模块的 UI、业务入口、状态、数据保存和必要验证尽量一次成组完成，避免十几次零散补丁。
4. **减少盘点与测试空转。** 初始恢复只做一次快速定位；已证实的内容不重复扫描。只执行与本批次风险相匹配的最小测试，模块阶段完成后再做模块回归，整合节点才跑完整验证。
5. **每个有效阶段持久化到 GitHub。** 功能批次提交时，同时更新本项目的实时进度文件，确保断线后新窗口能恢复“做到哪里、下一步做什么”。
6. **允许并行。** 对独立页面、不同模块和不同源文件并行检索、分析和实施；共享文件（`MainActivity.java`、Manifest、Gradle、统一状态/配置文件）由一个整合顺序处理，避免覆盖冲突。不能真正启动多 Agent 时，不得谎称启动了多 Agent；应使用并行工具调用完成多线推进。

“自动优化到完美”是持续质量目标，不得把“完美”当成无证据的完成声明。必须以真实代码、运行结果和测试证据描述完成度。

## 1. 每次新窗口的启动动作（只做一次，不反复盘点）

接手后按下面顺序执行：

1. 重新读取资料库 `/FX` 内的两份长期交接档和本文件；若本文件已在资料库中，不能要求用户再次介绍项目。
2. 读取 GitHub `vip-svip/SY` 指定分支的**最新 HEAD、最近提交、当前实时进度文件**。旧 SHA 仅是历史线索，绝不作为当前版本。
3. 只针对当前准备开发的页面/功能，读取相关 UI、路由、Activity、资源、业务实现和原始 APK/Manifest/Smali 对照资料。不要把全仓库审计当作每轮的第一项工作。
4. 将任务分成 UI 页面组、后端能力组和 P0 安全/稳定性组。**UI 页面组优先推进**；若遇到会造成断网、数据丢失、权限越界、崩溃或误报安全的 P0 风险，可立即并行修复，不必等待 UI 批次结束。
5. 选出一组范围明确、能在本轮实际完成的页面/功能，直接开工。不要再输出长篇新计划，不要问用户已经明确过的问题。

若最新 GitHub HEAD 与实时进度文件不一致，以 HEAD 为准，并把进度文件修正；如果分支在编辑过程中继续前进，必须从新 HEAD 重读目标文件再提交，禁止覆盖新内容。

## 2. UI 优先的开发顺序

### 阶段 A：FX 主应用六 Tab 外层

固定六 Tab，顺序不可更改：

1. VPN
2. Ad / Hosts
3. 隐私
4. 脚本
5. Hook
6. 设置

先完成以下可见 UI 质量：

- 六个 Tab 始终可见、顺序固定；底部栏高度、图标/标题、选中态、页面滚动和软键盘适配正确。
- 修复顶部错误横幅遮挡、底部导航消失、VPN 开关/模式控件错位、页面切换状态丢失等历史反馈。
- 旋转、Activity 重建、返回、前后台切换后，恢复当前 Tab、迁移层级、Hook 目标和正在编辑的数据。
- 页面标题、返回路径、加载中、空数据、错误、无权限、不可用状态要清楚。
- 不得把 VPN、Hosts、隐私、脚本、Hook 或迁移应用的业务错误塞入设置页面。

**重要：** 当前 `MainActivity` 已有六 Tab 状态字段（`selectedBottomTab` / `lastWebTabIndex` 的范围为 0–5）、Hook/Settings/Migration 导航状态保存，以及若干原生 Activity。项目也保留一个用于旧版 API/状态桥接的内嵌 WebView 兼容运行时。不要把“已有 MainActivity”或“存在 WebView 页面”当作 UI 迁移完成。新 UI 必须优先使用原生 Android 页面；旧桥接仍被真实功能依赖时，先迁移调用方再逐步退役，禁止贸然删除造成回归。

### 阶段 B：三套迁移应用的导航和页面 UI

设置始终为第六 Tab。“迁移应用”入口下面必须有三个互相独立的三级页面：

- Dia 23.11
- 游龙广告插件 7.0.1
- 游龙安全护盾 9.9.60

各应用原有页面作为四级及更深层页面。不能把三套应用压扁成说明卡片或放入一个泛化杂项页。

先按原始 APK 的 Manifest、菜单、布局、资源和页面跳转，完成完整页面目录/路由；再逐页补齐原控件和真实操作。所有菜单、弹窗、编辑器、列表、表单、二次确认和返回链都要在对应应用的子树内。

### 阶段 C：各主 Tab 的 UI 页面批次

**VPN 页面优先：**
- VPN 总开关、直连/全局/规则模式、节点、订阅、连接状态、错误状态、DNS/代理状态和应用规则入口。
- 不增加用户已明确删除的“快速配置”；不在 VPN 页面擅自增加“应用”区。
- 直连无节点可用；模式选择和按钮状态必须与后台真实状态一致。
- 不得只画一个开关。UI 需覆盖连接中、已连接、失败、第三方 VPN 占槽、Root Proxy 可用/不可用等状态。

**Ad / Hosts 页面：**
- Ad 与 Hosts 的显示入口可融合，但业务数据必须分清：系统本地 Hosts、订阅规则、允许/阻止列表、白名单和过滤来源不能混成一张订阅列表。
- Hosts 编辑页面必须是实际文本文件编辑器，有读取、搜索、分页/增量加载、保存、差异/外部修改提示、备份/回滚入口；不得用订阅规则列表假扮 Hosts 文件。
- 广告规则订阅、导入、更新、失败状态、规则来源/数量和过滤状态必须可见。

**隐私页面：**
- 按既有分类展示面板、目标应用、开关、权限状态、白名单和运行状态。
- 每个控件有来源说明、真实系统权限状态、不可用原因和保存反馈；不做“看起来可开但没有后端”的假开关。
- 反诈、隐私、跟踪、广告、Hosts 规则分类分开。FX 反诈规则仅限大陆反诈中心/96110 相关规则；水印去除和开屏广告规则不得混入反诈规则。

**脚本页面：**
- 脚本列表、搜索、导入/导出、编辑器、语法/类型提示、运行/停止、定时任务、权限与日志页面。
- 运行时未接通的能力必须明确标出“未接入/暂不可用”，不能伪造执行成功。编辑器、列表和任务页面可以先完成原生 UI，再按能力清单接通引擎。

**Hook 页面：**
- Hook 首页显示真实权限/模块状态；应用列表展示图标、应用名、包名、搜索和筛选。
- 点击应用进入该应用独立配置页；会员相关选项、自定义 Hook 区、规则组、状态、日志、导入/导出要在目标应用页面内组织。
- Root、LSPosed/LSP、Accessibility 和 Android 原生权限来自系统真实查询；文件写入成功不等于 LSPosed 注入成功。
- 自定义规则多语法要有规则选择/编辑/校验/预览/执行状态 UI；未支持的语法必须明确标识，不可静默忽略。

**设置页面：**
- 必须始终是第六 Tab。
- 系统选项、权限、备份/恢复、迁移应用和关于信息各自分组；三套应用有独立入口。
- 不得把其他 Tab 的主体功能迁到设置里。

### 阶段 D：前端页面完成后，按页面接通后端

按已完成 UI 的页面顺序推进对应后端，形成垂直功能闭环：

- 一个页面的可见控件 → 唯一明确的数据/配置键 → 业务 API/Root/服务/引擎 → 状态回读 → 错误提示 → 持久化/回滚。
- 保存后重新读取后端值，不能仅更新按钮颜色或本地临时变量。
- 服务状态以真实进程、系统接口或 Root 结果为准，不能以 SharedPreferences 的旧值冒充运行状态。
- 未完成的按钮应禁用并解释原因，不能给出假成功 Toast。
- Root 命令必须参数化、转义、限时、限路径和限 allowlist；路径需检查符号链接与父目录；文件写入先临时文件、权限、校验、原子替换和回滚。
- 所有服务/Receiver/Worker 需处理重复启动、并发、取消、超时、生命周期和异常退出。

## 3. 当前主要待办与主动查漏方向

以下是持续排查范围，不是未经核实的“全部缺失清单”。每一项必须标记状态：`未检查 / 缺失 / 部分实现 / 已实现未验证 / 已验证 / 有意不迁移（说明原因）`。

### A. Dia 23.11

当前仓库已有多个原生 Activity/服务/路由，如 Frida、代码编辑器、备份、DEX 浏览器、文件浏览器、Inspector、JSON、签名、Activity 浏览器、全局设置、System Expand、Wi-Fi 代理、Crash 报告等；但这不等于 Dia 完整迁移。

优先继续：
- Frida WAIT/RESUME/listener/message 转发、server/injector/gadget 的安装/移除/连接/断开/目标进程校验和错误恢复。
- 原生 JS 编辑器、脚本库、保存/执行/停止、运行上下文、权限、超时、日志和脚本状态恢复。
- 原应用类/方法/字段 Hook 页面、扩展管理、剩余设置和系统扩展控制。
- 原始页面/组件清单与 FX 页面路由逐项对照，补齐未映射的 Activity、菜单、弹窗、Service、Receiver、Provider。
- 现有 Frida 监控模板不等于原始内置监控引擎；必须诚实标记模板能力与完整运行时能力的差别。
- LSPosed scope 同步、目标进程注入和原包名适配未验证前，保持清晰的限制状态，不得声称完成。

### B. 游龙广告插件 7.0.1

当前已有原生 Ad、General、Summary、Stats、App Whitelist、DNS、Firewall 页面和部分广播/定时任务/Root Proxy 接入，但仍需核对：
- 原始广告规则解析、Trie/Bloom 数据格式、订阅错误恢复、规则冲突优先级。
- 本地 Hosts 编辑和订阅规则分离是否真正落到系统 hosts/实际过滤路径。
- DNS 上游协议、缓存、失败回退、私有 DNS、VPN DNS 和 Root Proxy 实际路由。
- 每应用 DNS 请求/拦截计数、不同厂商 VPN 接口和外部 VPN 兼容范围。
- 原 Tile/Widget/Tasker、通知、开机恢复和调度 UI 的真实状态同步。
- 不得启动与 FX 竞争的第二个 VpnService；所有兼容声明要说明路径和限制。

### C. 游龙安全护盾 9.9.60

当前已有 Shield Hub、名单、扫描、病毒库、告警、批量清理、完整性/日报、Screen Filter、Rescue 和部分 Stellar 管理页面，但仍需核对：
- 原始主界面、风险详情、清理队列、取消/重试/回显、名单编辑和数据库更新状态。
- Stellar 原始组件与权限/命令能力的全量映射；当前安全命令 allowlist 与原版 Golden Dragon/Stellar 运行时并非完全等价。
- 原始 KeepAliveAlarm/watchdog、开机恢复、权限降级后的修复流程、原始 Rescue Overlay 的差异。
- 扫描范围、APK 内容读取失败、数据库未就绪或扫描超预算必须标记不完整，不可误报安全。
- 保持 Stellar 在安全护盾内部，不得新增主 Tab。

### D. FX Hook：API-82/API-101 与 75 个历史开关

- 单 APK 双入口结构不等于 75 个历史开关全部迁移到现代 API-101。
- 当前应按 `docs/FX-API82-TO-API101-MIGRATION-PLAN.md` 和 `docs/FXHOOK-MIGRATION-MATRIX.md` 的逐项矩阵继续；旧入口保留的项目、API-101 已接管项目、故意 fail-closed 项要区分。
- 先完成用户可见 Hook 首页、应用列表、逐应用配置、权限状态、规则管理与诊断 UI。
- 继而按能力组实现解析、序列化、发布、运行时适配、去重/冲突防护和卸载更新同步。
- 会员/服务端授权、LSPosed scope、实际注入不可由 UI 草稿或配置写入推定为成功。

### E. VPN / DNS / Hosts

- VPN 单槽位架构必须使用共享 VpnService/TUN ingress，并在内部拆分代理、DNS、广告过滤和隐私管线。
- 直连、全局、规则、节点/订阅、DNS、外部 VPN 占槽和 Root Proxy 的 UI 与后端一致。
- Hosts 操作真实系统文本文件；支持外部编辑器修改回读、冲突检测、分页/增量、大文件、原子写入和回滚。
- 检查网络切换、休眠唤醒、上游不可达、Root 授权失效、第三方 VPN 切换时的恢复路径。
- 未经 OnePlus 12 或实际设备测试，不得宣称完整流量路径、DNS 泄漏或第三方 VPN 共存已验证。

### F. 隐私与脚本

- 隐私页面 UI 先行，随后逐面板接通真实 Root 配置、Android 权限和 Hook 行为；区分“应用内模拟”与“系统级改动”。
- QuickJS/QuickJS-NG、NDK r26b、ARM64 构建和各类脚本 API 兼容按能力分层，不得将头部识别称为完整兼容。
- `$httpClient`、`$task.fetch`、`$done`、`$prefs` 等 API 的网络、偏好、超时、取消、错误传播、资源上限和沙箱要有真实实现。
- 不可信脚本不得默认获得任意文件、Shell、Root 或网络权限。

## 4. 历史 Bug 与风险优先级

**P0：** 断网/VPN 槽位冲突、DNS 路由错误、Hosts 写坏或不能回滚、数据丢失、扫描误报安全、缓存被空响应覆盖、Root/Shell 注入、符号链接/路径穿越、密钥泄露、脚本越权、崩溃/ANR。发现即修，不必等待 UI 阶段。

**P1：** 六 Tab、原生页面与导航、三套应用 UI 完整度、统一 Hook 页面/权限、Dia/广告/护盾主业务、共享 TUN、DNS/Hosts 真实通路。

**P2：** 原始弹窗/编辑器/扩展/工具、交互细节、状态恢复、性能、无障碍、UI 自动化、可诊断性。

用户历史反馈需持续回归：顶部横幅、底部 Tab 消失/高度异常、VPN 开关和模式错位、订阅导入、页面返回状态丢失、原页面功能错放设置、隐私 UI 空壳、Hook 应用列表/独立配置缺失、长列表卡顿、编辑器大文件卡顿、权限与运行状态不一致、后台服务停止后 UI 仍显示运行、病毒库失败后误覆盖缓存、扫描不完整仍显示安全完成、Frida 页面重建丢失目标状态。

## 5. 禁止的低效做法

- 不要每个窗口重新写一份宏大计划；先读最新 HEAD 和实时进度，然后做事。
- 不要反复审计已经查证过的文件；只对本批次需要的代码做差异检查。
- 不要用十几个小提交制造进度感；同一功能组一次性修改并成组提交。
- 不要每改一行就触发完整 Actions；先用静态检查/单元测试/模块回归，到了阶段节点再整合。
- 不要反复修改测试脚本本身来绕过产品问题；测试失败时先读失败行、定位根因，再修实现或修正真实过时的契约。
- 不要只加文案、日志、卡片和按钮就声称 UI/功能完成。
- 不要使用假数据、假开关、假运行状态、空实现、外部 APK 启动或 WebView 伪装原生迁移。
- 不要删除原功能来让测试通过；对于不能安全迁移的原始功能，应保留原路径/数据并明确标为未迁移或不可用。
- 不要因为一个任务卡住就停止其他独立工作线。
- 不要要求用户反复确认已明确的需求。

## 6. 完整功能批次怎么做

每批次选择一个用户可见页面/功能组，流程如下：

1. **一次性查明原行为：** 从原 Manifest、Smali、布局、字符串和原应用路径确认控件及业务意图。
2. **完成 UI 与路由：** 页面结构、控件、列表、弹窗、输入校验、返回链、空/错/加载状态一次处理。
3. **接通真实状态：** 页面读取当前后端值；按钮执行对应 API/服务/Root 操作；操作完成后回读结果。
4. **补持久化与故障保护：** 配置保存、重启恢复、重复操作、取消、失败回滚和权限拒绝。
5. **做本批次最小有效验证：** 相关静态检查/单测/页面回归；高风险功能按风险增加验证。测试没跑就标“未运行”。
6. **成组提交：** 一组页面/业务改动一个清晰提交，提交说明写明实际行为。不要附带无关补丁。
7. **同批更新进度：** 修改 `docs/FX_1.0.0-LIVE-CONTINUATION-STATE.md`，记录新 HEAD、已完成页面、残留项、测试等级、下一批目标。
8. **复核后继续：** 重新读取提交 SHA、diff、关键文件，确认提交落地；直接开始下一组，除非遇到确需用户本人处理的授权/账号/不可逆操作。

### 测试节流规则

- 产品实现与 UI 页面是主要工时；测试用于防止回归，不是开发主体。
- 每组页面/功能只做一次针对性检查；多个共享依赖页面完成后做一次模块回归。
- 不因为每次 push 都自动排队 Actions 就重复推送微小改动；尽量在一个批次末尾推送一次。
- 整套 Actions 仅在阶段节点、构建链路变化、Manifest/资源/Gradle 大改或准备最终验收时运行。
- 对失败的 Actions 只读对应 job/失败步骤日志；不重复启动同一流程来“碰运气”。
- 对 UI 要做真实 UI 自动化/截图或设备交互时，如当前环境无设备，写清楚“未验证”，不要用源代码检查冒充视觉验收。
