## 2. FX 反诈保护的目标能力矩阵

| 子系统 | 计划能力 | 默认策略 | 关键限制 |
|---|---|---|---|
| 诈骗网址与域名 | 黑名单/信誉源、URL 结构风险、短链展开（安全沙箱）、Punycode/同形字符、品牌仿冒、IP 字面量、可疑跳转、域名年龄/证书线索（可用时） | 本地分析优先；高风险阻断、疑似警告 | 不得仅凭单一弱信号封禁；未知域名不等于诈骗 |
| DNS 风险拦截 | 将反诈域名判定接入 FX 现有 DNS/Ad 规则引擎；反诈策略与广告规则分开管理 | 反诈规则独立开关、独立统计和白名单 | 不迁入第二个 VpnService；不与 VPN 节点路由争抢 TUN |
| 短信诈骗识别 | 短信正文/发送方/链接/验证码诱导/冒充客服与公检法/贷款投资/快递退款/刷单等风险评分；中文优先，其他语言按模型覆盖 | 只分析用户授权范围；提示优先，自动处置遵循系统角色限制 | 不上传短信全文；Android 不允许普通广播接收器任意阻止/删除短信 |
| 来电风险 | 号码信誉、用户报告、号段/活动群组、异常频率、伪装/冒充信号；来电前或来电中提示 | 先提醒；只有系统 CallScreening 角色/设备支持时才拒接 | 保留紧急号码、联系人、用户白名单、近期主动联系号码的安全优先级 |
| 二维码风险 | 扫描二维码后解析 URL/支付/登录/Wi-Fi 等类型；打开前显示目的域名和风险理由 | 未知支付码显示二次确认；高风险 URL 阻断 | 不能声称能拦截所有第三方 App 内部二维码；只覆盖 FX 扫描入口及可观测的跳转链 |
| 行为风险 | 屏幕共享/录屏与银行/支付应用并发、陌生来电期间验证码到达、疑似远程控制/辅助功能滥用的风险提示 | 本地行为信号、分级告警 | 不读取其他 App 私密屏幕内容；MediaProjection/UsageStats/通知权限需明确授权；避免误报 |
| 反诈知识与应急 | 本地诈骗类型说明、风险原因、证据保存提示、96110/110/12381 等地区化求助信息 | 离线可用；明确地区与号码适用范围 | 不伪装官方身份、不代替警方/银行；紧急联系方式需核验和可配置 |
| 号码/域名反馈 | 一键标记诈骗/误报、白名单/黑名单、临时信任、撤销与审计记录 | 本地保存；用户主动提交前预览 | 社区上报默认关闭；最小化字段、匿名化、频率限制、去重 |
| 反诈遥测保护 | 继续独立审计 qufz 特定 ColorOS 遥测 Hook | 设备/包版本兼容时用户启用 | 不影响本地风险提示、系统通知和必要安全记录 |

## 3. 推荐的 FX 统一架构

采用「多信号检测 + 单一风险决策 + 多通道告警」；不把多个上游 App 拼装成多个服务。

1. **FraudSignal**：规范化信号模型，包含来源、类别、时间、证据类型、可信等级、地域、有效期、来源许可证与签名状态。
2. **FraudChecker Pipeline**：参考 CallShield 的 IChecker/优先级管线；统一白名单、紧急安全底线、用户明确阻止、信誉规则、启发式、模型评分和上下文行为。每个检查器可独立启停、单测和诊断。
3. **URL/DNS Engine**：参考 TianshangGuard 的同形字符、域名、DNS 与 URL 风险链；复用 FX 既有 DNS/TUN 服务，只接入一个共享决策接口。
4. **SMS Engine**：本地文本规则 + 轻量模型 + 链接提取；模型超时/加载失败时退回规则并标记覆盖不足，不阻塞系统广播热路径。
5. **Call Engine**：可选 CallScreeningService 适配器；统一 4.5 秒以内预算（留出 Android 回调余量），禁止在关键筛查链同步等待网络。
6. **QR Engine**：FX 内置扫描器/用户主动提交图片或内容后解析；风险结果在跳转前展示。
7. **Behavior Monitor**：只消费用户明确授权的 UsageStats、通知、MediaProjection/系统能力状态等元数据；权限撤销时关闭对应检测，不尝试绕过系统权限。
8. **Alert & Incident Center**：隐私 Tab 展示风险事件、来源证据、处置建议、白名单/误报操作和导出；保留用户本地控制。
9. **Rule Update**：版本化数据包、Ed25519 签名、时间戳/重放保护、哈希、原子更新、回滚、过期策略；更新失败继续使用最后一份有效规则并标记陈旧。
10. **Storage**：复用 FX 加密存储方案；短信正文、通话内容和用户提交证据默认不离开设备。日志默认只保留必要摘要/哈希/用户可见原因。

## 4. 中国大陆反诈规则与场景扩充

初始分类至少覆盖：
- 冒充公检法/国家机关、冒充运营商/银行/平台客服；
- 虚假征信修复、注销校园贷、贷款刷流水、刷流水返佣；
- 刷单返利、兼职任务、虚假投资理财、虚拟币/杀猪盘；
- 电商退款、快递理赔、机票/酒店退改签；
- 冒充熟人/领导、微信/QQ 换号、紧急借款；
- 假冒购物/支付页面、钓鱼登录、盗取验证码；
- 共享屏幕诱导、远程控制、辅助功能滥用；
- 二维码收款/付款码替换、假客服二维码、恶意 Wi-Fi 二维码；
- 虚假征婚交友、游戏交易、虚假中奖、虚假补贴。

数据源采用分级制度：
- A 级：官方公开且允许再分发的数据/公告，保留原始来源、发布日期、适用地区与复核日期。
- B 级：开源项目中许可明确的数据，保留 attribution、版本和上游限制。
- C 级：社区报告/用户反馈，必须多方佐证、反滥用、设定过期时间；单人举报不得直接全局封禁。
- D 级：模型推断/启发式信号，只用于风险评分或提醒，不当作事实黑名单。
- 不导入未经授权的个人号码库、泄露数据、短信样本或商业数据；不将 CallShield 的北美号码库直接套用到中国大陆。
- 96110、110、12381 是求助/预警相关号码，不得被当作诈骗号码加入拦截库；紧急/公共服务号码建立不可被普通规则覆盖的安全底线。

## 5. 隐私、安全与误报防护

- 默认本地推理；远端只拉取签名规则。任何外部查询必须单独开关、说明会发送的最小字段并在发送前提示。
- 短信正文、联系人、通话记录、二维码截图、剪贴板内容不得默认上传或用于遥测。
- URL 查询如需外部信誉服务，默认只提交规范化域名，不提交完整 URL 参数、令牌、路径中的个人标识。
- 所有规则需记录来源、许可证、签名、发布时间、更新时间、过期时间和回滚版本。
- 用户白名单与紧急联系人优先级高于低置信度模型结果；任何自动拒接都必须给出可撤销入口。
- 不因号码未收录、域名未知、模型异常就默认阻断；根据功能风险采用 fail-safe 提醒或回退。
- 模型必须提供版本、输入预处理、阈值、混淆矩阵、分语言/地区的误报率和召回率；缺少评估材料时仅标记实验能力。
- 不声称能识别所有诈骗，不承诺挽回资金，不替代警方、银行、运营商和国家反诈中心。
- 所有权限逐项说明用途；无权限时展示能力降级，不循环弹授权、不绕过系统安全机制。

## 6. Android/FX 集成约束

- 不新增第二个 VPN Service。TianshangGuard 的 GuardVpnService 不可原样并入 FX；只审计并迁移可复用的 LocalDnsEngine/域名判定逻辑，接入 FX 现有共享 TUN/DNS 管线。
- 短信接收权限、默认短信应用角色、通知访问权限必须分开呈现；不能把收到 SMS_RECEIVED 广播说成能删除/阻止短信。
- 来电筛查需确认设备/Android 版本、角色和系统 OEM 行为；不支持时退化为号码查询/事后提醒。
- 屏幕共享检测必须遵循 Android MediaProjection 用户授权与系统版本行为；不能静默捕获屏幕。
- OPPO qufz Hook 仅在包名、签名/版本、方法签名和 ColorOS 条件匹配时启用；其他设备 fail-closed。
- 模型、词表、训练数据、域名/号码库分别核验许可证、体积、内存、启动耗时、CPU/NPU/NNAPI 兼容性和耗电。
- 反诈规则与 Ad 广告规则、FX 专属 96110 相关规则、VPN 代理规则严格分离；各自独立开关、命中记录与白名单。
- 第三 Tab 隐私中的反诈主页应展示：总开关、实时状态、最近风险、短信/来电/网址/二维码/行为/遥测保护各子项、规则更新状态、权限缺口、白名单和误报反馈。不可把未接入项显示为运行中。

## 8. 当前结论与待用户确认

推荐方案：把 TianshangGuard 的本地 URL/DNS/短信/二维码/行为风险检测，与 CallShield 的模块化来电/短信决策链，和 qufz 的 ColorOS 定向遥测 Hook，统一纳入 FX 隐私 Tab 的「反诈保护」域；共享 FX 已有网络、存储、通知和权限基础设施，不复制 VPN 服务、不保留第二个 APK 入口。

本文件仅是方案和来源审计结果。**未迁移源码、未新增权限、未更改 Manifest、未修改 UI 或业务实现。** 用户确认本方案后，才进入逐文件实现阶段。
