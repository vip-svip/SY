# FX built-in optional "remove watermark" domain set.
#
# Purpose: block the *network* side of watermarking. Many Chinese apps do not render
# the watermark locally; they fetch it, the badge template, or the "who viewed this"
# overlay from a server, so a DNS rule removes it before it ever reaches the view.
# Pixel-burned watermarks written into exported photos/videos cannot be removed at the
# DNS or DOM layer - that needs the image pipeline (see the note at the bottom).
#
# Format: hosts (0.0.0.0 <domain>), same DNS/hosts pipeline as
# rulefiles/privacy_ad_domains.txt. Disabled by default.
#
# Scope rules used when building this list:
#   * only watermark/watermark-template/badge hosts, never a content or CDN root
#   * never a bare registrable domain that also serves user-facing traffic
#   * no wildcard-only entries; every line is a concrete host

# NOTE on pixel-burned watermarks:
# A watermark already written into exported JPEG/PNG/MP4 pixels is not a network
# fetch, so no DNS rule can remove it. Removing that class requires decoding the
# image, locating the overlay band and inpainting it - the image-pipeline work
# tracked separately from this rule set. Claiming otherwise would be a false claim.
