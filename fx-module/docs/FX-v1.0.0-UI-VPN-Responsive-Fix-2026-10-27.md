# FX 1.0.0 UI VPN 窄屏修复记录（2026-10-27）

## 修改范围

- 不改模块固定版本号（仍为 `1.0.0`），不重设计原页面风格。
- 移除 VPN 页独立的“应用当前模式”按钮；直连/全局/规则模式统一走即时应用入口。切换全局/规则前必须已选节点，正在应用时会拒绝重复切换；检测到外部 VPN 且未启用叠加兼容时不会启动 FX 透明接管。
- VPN 状态栏的代理总开关、启动核心、停止核心在宽屏保持一行/自动换行，小屏使用明确的网格控件布局，压缩因 flex 自由伸缩造成的拥挤。
- 状态摘要四栏在 600px 以下改为两栏；避免节点名或状态值挤压到极窄宽度。
- 外部 VPN 诊断行采用响应式结构，文案说明实验性叠加不能被按钮状态等同为链路已打通，仍要检查出口并用真实应用确认。
- 底部导航安全区不再同时通过内部 padding 和外部 margin 重复占用。

## 验证

- 新增 `scripts/tests/v1.0.0-ui-vpn-responsive-controls-regression.sh`。
- 新回归、VPN toggle、外部 VPN 状态/DNS fail-open、UI 启动/导航恢复、配置事务、直连无节点等 11 项重点测试通过。
- 全仓 Shell 脚本 `sh -n` 检查通过；UI 的 31 个内联脚本均可被 Node.js 解析。
- 没有 OnePlus 12 真机视图/触控验证。容器中的 Chromium 无法在时限内生成整页截图，因此不把静态 DOM/CSS 检查说成真机视觉验收。

## 仍然保留的功能边界

- 外部 VPN 共存不是 UI 改动就能保证；实验叠加仍需检查路由、UID、真实出口和 DNS 路径。
- 只调整 UI 交互调用现有 apply 管线，没有修改 VPN 透明代理或 DNS 的底层流量路径；外部 VPN 的默认共存机制仍需单独验证，不能仅凭 UI 认为链路已经打通。
