# FX 1.0.0 运行时审计记录（模块 ID privacyguard 保持升级兼容）


## 2026-10-27 运行时联动与并发修复补充
- 脚本订阅同步增加原子目录锁，串行化手动刷新、定时刷新和引擎启动触发的缓存写入；避免并发同步用各自过期的 active 清单误删对方刚安装的脚本。异常退出后会识别并回收陈旧锁；锁持续忙碌时明确失败，不继续改写缓存。
- 脚本列表开关、编辑、删除和第三方模块导入后自动触发运行时清单同步；导入时刷新 MITM hostname 白名单、URL Rewrite 和脚本缓存，且只有全部同步成功才报告“运行时清单已同步”。
- 第三方模块导入提示区分“配置已写入”与“运行时清单已同步”；任何运行时同步失败都明确指出相关脚本不应视为生效；对于格式/触发条件不受支持的声明，明确提示跳过项不会执行。
- 脚本界面新增真实状态诊断和分开的启动引擎/启用拦截/关闭拦截操作。TCP/443 重定向仍默认关闭，并要求用户显式确认；无 root 桥接、CA 信任不符或 VPN 冲突时不宣称已生效。
- 请求/响应脚本不能自行控制 `Content-Length`、`Transfer-Encoding` 等 HTTP 消息边界头；由引擎统一修正正文长度和传输字段，减少脚本改写正文后截断响应或连接失效的风险。
- 追加并发同步回归，确认两次同步串行完成后脚本与 SHA-256 sidecar 仍一致，锁在正常退出时清理。

## 2026-10-27 主动缺陷排查与运行时加固
- 安全审计新增重要限制说明：QuickJS-NG CLI 即使隐藏 `std` / `os` 全局别名，也仍注册系统模块加载器；这不是强沙箱，远程脚本可能尝试动态导入系统 API。此包尚未实现无特权脚本隔离，必须只运行可信脚本，不能将自动下载的第三方代码视为安全。
- HTTP 脚本桥接移除不具备可移植重定向协议限制的 `wget` 回退；没有 `curl` 时明确失败关闭，避免 HTTPS 请求在重定向路径中被降级为 HTTP。
- QuickJS `$done()`：只有实际调用 `$done()` 才会保存成功结果；正常退出但未完成回调时明确报错，不再误判为成功空操作。
- 脚本运行资源保护：ARM64 QuickJS 每次执行限制为 64 MiB 堆内存和 1 MiB 栈；MITM 对脚本 stdout 限制 2 MiB、stderr 限制 256 KiB，避免异常输出无限占用宿主内存。
- 脚本超时清理：将脚本 runner 放入独立进程组；达到 12 秒时终止整组进程，减少 `qjs`/`curl` 子进程在请求失败后继续运行的风险。
- Hook 加载：移除静默的 32 个脚本硬上限；主机侧回归确认 40 个有效 Hook 均能被扫描加载。多个脚本匹配同一请求时执行耗时仍会累加，应避免大批脚本重复匹配。
- MITM 透传：半关闭连接现在等待双向复制结束，避免客户端结束发送后上游响应被提前截断。
- MITM 范围：按已导入的 `[MITM] hostname` 白名单执行解密；未命中、无 SNI 或名单异常时透传原始 TLS，而不是向任意 HTTPS 主机呈现 FX CA。
- 规则配置：公共列表读取器合并同名 `[list:*]` 段；第三方远程文本 `RULE-SET` 仅在受支持扩展名和 REJECT 策略下进入现有缓存/校验/路由编译链，不把不支持格式伪装成生效。
- KernelSU 包结构：`module.prop` 精简为合法的模块元数据键值，打包时将其放在 ZIP 根目录；不把 `AUDIT###` 历史审计报告作为模块运行文件打包。
- 验证边界：以上是源码级、主机侧回归与 Android arm64 交叉编译验证；本轮没有 OnePlus 12 真机测试，也没有验证证书固定、QUIC/HTTP3 或第三方 VPN 的全部行为。

## 本轮变更
- 通用下载器改为严格处理 HTTP 状态：curl 使用 `-f`，HTTP 4xx/5xx 不再被当作成功正文缓存。
- 下载器不再关闭 TLS 证书校验（移除 `--insecure` / `--no-check-certificate`）。证书异常或自签名源可能因此下载失败；失败应走现有缓存回退，而不是接受不可信响应。
- Hosts 订阅下载器采用同样的 HTTP 状态与 TLS 校验策略。
- 新增 `scripts/tests/v1.0.0-http-fetch-integrity-regression.sh`，覆盖 HTTP 错误页不得被判成功、有效响应可下载。
- 公开版本号继续固定为 `1.0.0`。
- 本轮后续增补已修改 `webroot/index.html`，接入脚本订阅刷新；不能再把 WebUI 描述为与旧基线字节级一致。

## 仍需区分的运行时边界（不得误报）
- 本地 hosts 卡片目前是单个无扩展名文件入口，分页编辑的是 `$PG/local/hosts` 独立本地源；不是直接编辑由 `apply.sh` 聚合生成并 bind-mount 的 `/system/etc/hosts` 活动结果。应用时系统 hosts 会按各个单独存储的来源重新生成。
- 远程订阅保存在各自的订阅缓存/规则清单，不写入本地 hosts 源文件；但生效时，订阅域名与本地 hosts 都可能进入聚合生成的系统 hosts 输出，因而不能声称活动系统文件与订阅策略完全隔离。
- 尚未在 OnePlus 12 真机上验证；VPN 共存测试是主机侧/静态回归，不代表所有第三方 VPN 都兼容。
- 本轮没有实现订阅 SHA-256 来源校验；HTTP/TLS 校验不能替代内容签名/摘要验证。

### 本轮增补：订阅缓存双代回滚保护
- 为每个下载缓存保留一份已校验的上一代内容及 SHA-256 sidecar。
- 在替换当前缓存前先写入并校验上一代备份；如果更新中断导致当前缓存与 sidecar 不匹配，则仅在上一代文件和摘要匹配时恢复。
- 该 SHA-256 仍是本地静态完整性检查，不验证远端发布者身份，也不是签名验证。
- 回归测试覆盖：首次下载、成功更新、模拟当前缓存损坏/替换中断、网络失败时恢复上一代、无有效缓存时拒绝不完整下载。
